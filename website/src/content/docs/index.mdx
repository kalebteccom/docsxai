<div class="docsx-section not-content">
  <h2 class="docsx-section-title">Why it exists</h2>
  <div class="docsx-section-sub">
    Screenshot docs rot when the UI moves. docsxai treats them as build output: the flow is the
    source and a re-run is the refresh.
  </div>

  <div class="docsx-grid">
    <div class="docsx-card">
      <span class="docsx-card-mark">// execution</span>
      <h3>Deterministic CI replay</h3>
      <div class="docsx-card-text">
        A frozen clock and a pinned locale, timezone and viewport give byte-identical screenshots.{" "}
        <code>run --verify-determinism</code> names the first artifact that differs, and{" "}
        <code>diff --fail-on warn</code> fails CI on drift from a committed baseline.
      </div>
    </div>
    <div class="docsx-card">
      <span class="docsx-card-mark">// variants</span>
      <h3>One flow, many variants</h3>
      <div class="docsx-card-text">
        A <code>matrix</code> block runs one flow per locale, color scheme and viewport, up to 64
        combinations. <code>pack --check</code> compares the screenshot pack with the committed one.
      </div>
    </div>
    <div class="docsx-card">
      <span class="docsx-card-mark">// calibration</span>
      <h3>An agent writes it once</h3>
      <div class="docsx-card-text">
        An agent writes the flow through the Claude Code plugin, with lint and diagnose at write
        time. Every run after that is agent-free: no model in the loop, no token bill per refresh.
      </div>
    </div>
    <div class="docsx-card">
      <span class="docsx-card-mark">// output</span>
      <h3>Viewer or plain PNGs</h3>
      <div class="docsx-card-text">
        An interactive viewer with halos and callouts, or captions burned into plain PNGs for places
        that can't run the viewer. Redactions mask sensitive UI before any pixel hits disk.
      </div>
    </div>
    <div class="docsx-card">
      <span class="docsx-card-mark">// captions</span>
      <h3>Themeable burned captions</h3>
      <div class="docsx-card-text">
        Halo, badge, callout and connector follow a <code>burn.theme</code> block: four presets, an
        optional design-tokens file and per-key overrides. The viewer reads the same theme. Caption themes are on the main branch.
        <a href="/guides/burn-theming/">Read the burn theming guide</a>
      </div>
    </div>
    <div class="docsx-card">
      <span class="docsx-card-mark">// plugins</span>
      <h3>Publishers and renderers as plugins</h3>
      <div class="docsx-card-text">
        Publishers, renderers, lint rules and auth strategies plug in through a sha256-locked
        runtime. First-party publishers cover Confluence, GitBook, Guru, Notion and SharePoint.
        SharePoint is on npm as an experimental package. The others are repo-only for now.
      </div>
    </div>
  </div>
</div>

<div class="docsx-section not-content" id="first-run">
  <h2 class="docsx-section-title">First run</h2>
  <div class="docsx-section-sub">Five steps against an app on your machine.</div>
  <ol class="docsx-steps" role="list">
    <li class="docsx-card docsx-step">
      <span class="docsx-card-mark">// step 1</span>
      <h3>Make a workspace</h3>
      <CopyCommand
        command="docsxai init my-docs --app-url http://localhost:3000 --auth none"
        label="Copy the init command"
      />
      <div class="docsx-card-text">
        Keep it outside your app's repo. Behind a login? Drop <code>--auth none</code>, then run{" "}
        <code>docsxai capture-auth my-docs</code>.
      </div>
      <p class="docsx-expect">
        <span class="docsx-expect-label">Expect</span>
        <code>
          {
            "created: flows/, docs/, auth/, .auth/, .viewer/, .gitignore, .docsxai.json, flows/example.flow.yaml.sample, README.md"
          }
        </code>
      </p>
    </li>
    <li class="docsx-card docsx-step">
      <span class="docsx-card-mark">// step 2</span>
      <h3>Check the setup</h3>
      <CopyCommand command="docsxai doctor my-docs" label="Copy the doctor command" />
      <div class="docsx-card-text">
        Checks Node, Chromium and your app. A failing line ends with its fix.
      </div>
      <p class="docsx-expect">
        <span class="docsx-expect-label">Expect</span>
        <code>{"ok: config: .docsxai.json fields are valid"}</code>
      </p>
    </li>
    <li class="docsx-card docsx-step">
      <span class="docsx-card-mark">// step 3</span>
      <h3>Calibrate with an agent</h3>
      <CopyCommand
        command={"/plugin marketplace add kalebteccom/docsxai\n/plugin install docsxai@docsxai"}
        label="Copy the Claude Code plugin commands"
      />
      <div class="docsx-card-text">
        Then ask Claude Code: "calibrate my-docs: open Reports and show the export button".
      </div>
      <p class="docsx-expect">
        <span class="docsx-expect-label">Expect</span>
        <code>{"next: docsxai run my-docs  (then: docsxai render my-docs)"}</code>
      </p>
    </li>
    <li class="docsx-card docsx-step">
      <span class="docsx-card-mark">// step 4</span>
      <h3>Run it</h3>
      <CopyCommand command="docsxai run my-docs" label="Copy the run command" />
      <div class="docsx-card-text">
        Replays the flow in headless Chromium. No agent from here on.
      </div>
      <p class="docsx-expect">
        <span class="docsx-expect-label">Expect</span>
        <code>{"run: 1 of 1 flow ok, outputs in my-docs/docs"}</code>
      </p>
    </li>
    <li class="docsx-card docsx-step">
      <span class="docsx-card-mark">// step 5</span>
      <h3>Open the docs</h3>
      <CopyCommand command="docsxai render my-docs" label="Copy the render command" />
      <div class="docsx-card-text">
        Open the printed page. Hover or tap a halo to read its callout.
      </div>
      <p class="docsx-expect">
        <span class="docsx-expect-label">Expect</span>
        <code>{"render: open /path/to/my-docs/.viewer/index.html"}</code>
      </p>
    </li>
  </ol>
</div>
