# Changelog

All notable changes to this project. Format loosely follows [Keep a Changelog](https://keepachangelog.com/); this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security

- **Guru publisher: card read without `collection`.** A page card whose read carried no `collection` failed the target-collection check as intended and was recreated on every push with a warning per section that blamed the wrong cause. The check is unchanged and still fails closed; the plugin now logs one masked warning per push that says Guru returned the card without a collection and that new cards are created until it does, and the README says the same. The manifest card still fails the push in that case.
- **Request guard: lookup deadline.** `requestProblem` gave a hostname lookup no time limit, so a stalled resolver left the request pending. A lookup now has 5 seconds (`lookupTimeoutMs` on the guard options) and a request whose lookup times out is refused like any other failed lookup. `SECURITY.md` also says that on a CDP-attached context the guard cannot block service workers.
- **MCP token file on Windows.** `serve --http` prints one stderr warning when it reads a `--token-file` on Windows, where the permission check cannot run. The README and `SECURITY.md` now say `--token-file` is the preferred source, because the initial environment block stays readable to other processes of the same user even after the variable is cleared.
- **`upload` paths: hidden and reserved files refused.** The upload confinement allowed `.auth/<role>.json` (a captured storage state), `.docsxai.json` and `webhook-job.json`, which are inside the workspace. A value with any segment that starts with a dot, or that names `webhook-job.json` (any case), is now refused by the driver and when the backend materialises a revision, and the driver applies the same rule to the real path of a symlink's target. The two copies of the rule stay in step through the parity test.
- **MCP HTTP transport: `cdp` and `baseUrl` confined.** `run_flows` and `diagnose_halt` passed `cdp` straight to `connectOverCDP`, and `run_flows` took any `baseUrl`, so an HTTP client could attach to a browser on the server's host or point a run at a metadata address. With `serve --http`, `cdp` is refused, `baseUrl` (and a workspace `app_url`) must be an http(s) URL whose host passes the engine's address rules, resolved the way the request guard resolves it, and every browser a tool starts gets the request guard (`DOCSX_EGRESS_GUARD=0` switches it off; `DOCSX_EGRESS_DENY_PRIVATE` adds the private ranges). stdio is unchanged. `@docsxai/engine` now exports the `egress-guard` module (`requestProblem`, `envFlagOn`, `envFlagOff` and the rest).

### Fixed

- **Confluence publisher: attachment upload.** A live run against Confluence Cloud created the page, then `POST /wiki/api/v2/pages/{id}/attachments` answered 405 METHOD_NOT_ALLOWED, because v2 only reads attachments. Uploads now go to `POST /wiki/rest/api/content/{pageId}/child/attachment` (multipart `file`, `comment`, `minorEdit`, header `X-Atlassian-Token: no-check`), a changed screenshot is posted to `.../child/attachment/{id}/data`, and the media file id comes from `extensions.fileId` in the response. A publish that fails after creating a page now throws a `ConfluencePublishError` carrying `partial.pages` (and logs a `page_map` fragment), so a retry updates that page instead of creating a duplicate. The fake Confluence server in the tests models the 405 and the v1 response shape.

### Added

- **Sample repo for the CI recipes.** `examples/ci/sample-repo/` is a minimal workspace (flow, committed doc pack, committed baseline, `pack.json`) built from existing engine and viewer fixtures, and a test runs each recipe's `run --verify-determinism` and `diff` lines against it, plus `pack` and `pack --check`. The diff and pack steps need no browser; the determinism step skips without Chromium.

## [0.3.0-rc.1] - 2026-10-06

Prerelease, published under the `next` dist-tag. `0.2.0` stays `latest`.

### Added

- **Breaking: `upload` steps are confined to the workspace.** `PlaywrightDriver.upload` resolved its value against the workspace root and accepted an absolute path, so a flow could hand `/proc/self/environ` or a private key to the page it drives. The value must now be a path relative to the workspace with no `..` segment, naming a regular file whose real path (symlinks followed) is under the root; anything else fails the step with `upload path "..." is outside the workspace` or a sibling message. Materialising a backend revision refuses a flow file with an absolute or `..` upload value as well. The backend and the engine each hold a copy of the spelling rule, and a test in `packages/docsxai` compares them.
- **Request guard and `navigate` filter for webhook runs.** A flow's `navigate` step took any absolute URL, so a tenant flow could screenshot `http://169.254.169.254/...` past the `app_url` filter, and a redirect or a DNS name could do the same. Materialising a revision now reads each flow file and refuses a `navigate` value that resolves (the way Playwright resolves it, so `//host/x` and `/\host` count) to an absolute URL `appUrlProblem` refuses or, when the project has an `app_url`, to one outside its origin; relative values pass. `launchPlaywrightSession` takes an `egressGuard` option and reads `DOCSX_EGRESS_GUARD` (`1`, `true` or `yes`): a context route checks every request, each redirect hop included, resolves a host name with `dns.lookup` for all its addresses and aborts the request when one is link-local or a cloud-metadata address, when the lookup fails or returns nothing, or when the scheme is not `http(s)`, `ws(s)`, `data`, `blob` or `about`; service workers are blocked on a guarded context. `DOCSX_EGRESS_DENY_PRIVATE` adds loopback, RFC 1918, CGNAT and unique-local addresses. The backend runner starts every webhook run's engine with the guard on (`DOCSX_EGRESS_GUARD=0` opts out) and the private ranges on when `DOCSX_BACKEND_DENY_PRIVATE_APP_URL` is. A local `docsxai run` is unchanged. The address rules gain `168.63.129.16`, 6to4 `2002::/16` and Teredo `2001::/32` (the embedded IPv4 address is checked, the Teredo client decoded), `64:ff9b:1::/48`, `fec0::/10` and `localhost.localdomain` (with `ip6-localhost` and `ip6-loopback`) under the private switch. Both packages carry a byte-identical `address-class.ts` that a test in `packages/docsxai` compares. `DOCSX_BACKEND_DENY_PRIVATE_APP_URL` now accepts `1`, `true` and `yes` in any case, and `doctor` flags any other non-empty value on it and on the two new switches (`0`, `false` and `no` count as off on purpose). `@docsxai/backend` gains a runtime dependency on `yaml`, the parser the engine already uses. The guard also routes WebSocket connections (`context.routeWebSocket`), and what a run prints for a refusal is generic (`address not allowed`, URL without userinfo or query), with the host and resolved address passed only to the `onBlock` callback. Not covered: DNS rebinding between the guard's lookup and the browser's; `SECURITY.md` says what to put around a hosted deployment. `docs/public-surface.md` ENV-11 and ENV-12, experimental.
- **`docsxai-mcp serve --http`.** An opt-in Streamable HTTP transport for `@docsxai/mcp`, with the same tool registry as stdio. It binds `127.0.0.1:8765` and serves `/mcp`. A bearer token of at least 32 characters is required, read from `DOCSX_MCP_TOKEN` or `--token-file` and never from an argument. A token with fewer than 8 distinct characters is refused, and so is a token file that group or other can access (POSIX). The variable is cleared from the environment once read, so spawned tool processes do not inherit it. The server refuses to start without one. A non-loopback `--host` needs `--allow-remote`, and TLS has to terminate in front. The `Host` header is parsed strictly as `host[:port]` and must name a loopback host, the bound host or an `--allowed-host`. An `Origin` must name one of those on the bound port, or match an `--allowed-origin` entry exactly. Bodies over 1 MiB get 413, a seventeenth session gets 429, and a session idle for 30 minutes closes. `--workspace-root <dir>` is required with `--http`: every path a tool receives has to resolve inside it, symlinks followed. `docsxai doctor` knows `DOCSX_MCP_TOKEN`. Experimental: `@docsxai/mcp` stays private.
- **`@docsxai/plugin-guru`.** A publisher plugin, `guru:push`, that pushes a doc pack into a Guru collection through the Guru public API. It takes the same ADF projection as the Confluence plugin and renders each document to HTML, one card per document (`POST /cards/extended`, then `PUT /cards/{id}/extended`). Screenshots are uploaded with `POST /attachments/upload` and embedded as `<img>` tags pointing at the Guru-hosted URL. Idempotent: a card titled `docsxai manifest` in the collection records the content hash of every card and the hash and hosted URL of every image, and a second push of unchanged content performs zero writes. Credentials are the Guru user email and user token, read from the environment variables named in `secretsEnv.email` and `secretsEnv.token` (defaults `GURU_USER_EMAIL` and `GURU_USER_TOKEN`), sent as HTTP Basic auth and masked in every log line and error. The base URL is pinned to `https://api.getguru.com/api/v1`, redirects are refused, every request times out (30 s for API calls, 120 s for uploads, the manifest write included), a card is updated only when it is in the target collection (a manifest entry pointing elsewhere creates a new card), hosted image links must match `https://content.api.getguru.com/files/view/<id>` exactly, responses are size-capped and attachment reads stay inside the workspace. Config keys are `collection_id`, `base_url`, `title_prefix`, `share_status`, `force` and `manifest_card_id`. The only declared capability is `egress:api.getguru.com`. The package is `"private": true` and not in `scripts/release-publish.sh`. Tests run against an in-process fake Guru server. `docs/public-surface.md` row PLUG-14, experimental.
- **`@docsxai/plugin-sharepoint`.** A publisher plugin, `sharepoint:push`, that pushes a doc pack to a SharePoint Online document library through Microsoft Graph. It takes the same ADF projection as the Confluence plugin, renders each document to markdown and uploads it with its screenshots (`PUT /drives/{id}/root:/{path}:/content`, images linked by relative path), so it is plain library files and not modern site pages. Idempotent: a `docsxai-manifest.json` next to the pages records the sha256 of every file written, and a second push of unchanged content performs zero writes. The bearer token is read from the environment variable named in `secretsEnv.token` (default `SHAREPOINT_TOKEN`) and masked in every log line and error. Config keys are `drive_id` or `site_id`, `folder`, `graph_base_url`, `title_prefix` and `force`. The only declared capability is `egress:graph.microsoft.com`. The package is `"private": true` for now: publishing it needs an npm trusted-publisher binding that is not set up, and it is not in `scripts/release-publish.sh`. Tests run against an in-process fake Graph server. `docs/public-surface.md` row PLUG-13, experimental.
- **`@docsxai/plugin-gitbook`.** A publisher plugin, `gitbook:push`, that pushes a doc pack to a GitBook space through the GitBook API. It takes the same ADF projection as the Confluence plugin and renders each document to markdown, one page per document. Content goes in through a change request: the plugin opens one (`POST /spaces/{id}/change-requests`), applies a content batch per changed page (`POST .../content`, with `insert_files`, `insert_page` and `update_page` changes) and merges it. Screenshots travel inline as base64 file uploads in the same batch, so egress stays on one host; a screenshot over 700,000 bytes is named in `warnings` and replaced by a caption. Idempotent: a hidden `docsxai manifest` page records the page id and content hash of every section and is written in the same change request, so an unchanged pack costs a page listing and a read of the manifest page, performs zero writes and opens no change request. A push that fails before the merge archives its change request. The API token is read from the environment variable named in `secretsEnv.token` (default `GITBOOK_TOKEN`) and masked in every log line and error. The base URL is pinned to `https://api.gitbook.com/v1`, redirects are refused, every request times out, responses are size-capped, a page is updated only when it sits directly under the target (`parent_page_id` or the top of the space) and attachment reads stay inside the workspace. Config keys are `space_id`, `base_url`, `parent_page_id`, `title_prefix`, `force` and `manifest_page_id`. The only declared capability is `egress:api.gitbook.com`. The package is `"private": true` and not in `scripts/release-publish.sh`. Tests run against an in-process fake GitBook server. `docs/public-surface.md` row PLUG-16, experimental.
- **Flow matrix.** A top-level `matrix:` key (`locales`, `color_schemes`, `viewports`; each 1 to 64 unique entries, product at most 64) expands one flow file into one variant per combination at parse time. A viewport is a preset name or `{ width, height }` with an optional lowercase `name`. Each variant overrides `environment` on the axes the matrix names, and its id joins the axes present as `<locale>.<color_scheme>.<viewport>` (`es-ES.dark.mobile`); expansion order is locales, color schemes, viewports, each as written. Steps and annotations take `only:` and `skip:` (a map from `viewport`, `color_scheme` or `locale` to a list; a value no matrix entry can match is a parse error), and annotations take `copy_by_locale` (exact tag, then language, else `copy`). `matrix` is not inherited through `extends`. Without a matrix the output layout and every output byte are unchanged. With one, `docsxai run` starts one browser per variant and writes `docs/<flow>/<variant>/{screenshots/, annotations.json, halts/}`; `annotations.json` gains an optional `variant` object (the schema id stays `docsxai/annotations@1`), a halt message names the variant (`[variant es-ES.dark.mobile] step ...`) and `FlowExecutionError.variant` carries the id. `run --variant <id>` runs one variant, `diagnose --variant <id>` diagnoses one, `lint` adds R015 (info, lists the variants) and R016 (warning, a `copy_by_locale` key no variant locale uses), `flow-tree` prints the variants, and `push`/`pull` carry variant directories. `docsxai-viewer render` and `burn` treat each `<flow>/<variant>` as a flow (`discoverFlows` takes `{ variants: true }`; `burn --flow <flow>` also selects its variants). Not covered yet: `baseline`/`diff`, `export playwright` (refuses a matrix flow) and the MCP `run_flows` and `diagnose_halt` tools (`runFlow` rejects an unexpanded matrix flow). Design: `docs/ai-context/architecture/flow-matrix-decision.md`; adoption sketch: `docs/ai-context/matrix-adoption-notes.md`.
- **`docsxai pack` and `docsxai pack --check`.** The screenshot-pack pipeline is a product feature instead of a script each consumer copies. `docsxai pack <workspace-or-raw-dir> [--from-raw] [--out <dir>] [--public-prefix <path>] [--no-optimise] [--generated-for <text>]` burns each step's annotations (the viewer's `renderBurn`, so `obstacles`, `placement` and the dark-connector outline apply), optimises the PNG losslessly with the external `oxipng` binary (`$DOCSX_OXIPNG_BIN` or PATH; a missing binary fails with `brew install oxipng` unless `--no-optimise`), names it `<flow>/<step>.<hash8>.png` from the final bytes and writes `manifest.json`. A workspace is read through a `pack.json` (`docsxai/pack-config@1`: which capture flow feeds which variant, plus alt text); a raw capture directory (`<flow>/<step>/<locale>.<theme>.<viewport>.png` with a sidecar, `step.json`, `flow.json`) is read with `--from-raw`. Files the previous manifest listed and the new one dropped are removed by exact path and nothing else in the output directory is touched. Loopback addresses and obvious secrets in a title, caption, alt text or callout stop the build. `docsxai pack <workspace-or-raw-dir> --check --against <pack-dir> [--threshold <pct>]` rebuilds in memory and compares with the committed pack: equal hash is unchanged, otherwise a pixel diff gives the changed share and region, and a change over the threshold (default 0.5), a resize, a new or missing variant or a committed file that does not match its name exits 1. Both run the viewer's command through the same bin resolution as `burn`, so the engine still does not depend on `@docsxai/viewer`; the `docsxai` meta package needs no change.
- **`docsxai/screens-pack@2`.** One manifest shape for both earlier ones (`docsxai/screens-pack@1` from the trackxai workspace, `docsxai/screens-manifest@1` from remotxai): `{ schema, generated_for?, flows: { <flow>: { title?, steps: { <step>: { caption?, alt, variants: { "<locale>.<theme>.<viewport>": { src, width, height, bytes, callouts: [{ index, copy, bbox? }] } } } } } } }`, text as `{ <locale>: text }`, keys sorted, no timestamps. Locales, themes and viewports are bounded patterns, not a fixed list. `@docsxai/viewer` exports `validatePack`, `buildPack`, `writePack`, `computeDrift`, `guardPack` and the converters `convertScreensPackV1` (returns the file moves it implies) and `convertScreensManifestV1`. `docs/ai-context/screens-pack-decision.md` records the choices and `docs/ai-context/pack-adoption-notes.md` lists the steps for each consumer to switch.
- **Public surface inventory and contract tests.** `docs/public-surface.md` lists 121 surface items (CLI, flow-file, doc pack and schema ids, plugin API, `BrowserDriver`, engine library, MCP tools, backend REST and OAuth, `DOCSX_*` variables, `.docsxai.json`, viewer, Claude Code plugin), marks each `stable candidate`, `experimental`, `internal` or `planned` with the reason, states the compatibility and deprecation policy (a `Breaking:` CHANGELOG line, one minor of deprecation, schema ids bump), and holds the 1.0 checklist. Eleven contract test files under `packages/{engine,backend,viewer,mcp,plugin}/test/contract/` compare the live surface with checked-in JSON snapshots: the CLI usage lines and exit codes, a dump of every Zod schema in `doc-pack.ts` (the flow matrix keys and the annotations `variant` included), the `docsxai/verify-determinism@1` report, the `BrowserDriver` signatures, the plugin API types and manifest, the backend route table and error codes, the MCP tool names and argument shapes, the `DOCSX_*` list, the viewer CLI, burn report and `docsxai/screens-pack@2` types, and the plugin's command and skill names. They need no browser. A normal run never creates or rewrites a snapshot; `UPDATE_CONTRACT_SNAPSHOTS=1` rewrites one and fails that run on purpose.
- **`wait_for: settled`.** A bounded page settle that needs no target: web fonts loaded (`document.fonts`), every `<img>` in the viewport complete, and the boxes of the viewport-visible elements (light DOM and open shadow roots) unchanged within 0.5 px on two consecutive polls. `PlaywrightDriver` runs a fixed in-page function every 50 ms after an animation frame; it takes four numbers and no selector, and nothing from the flow reaches the page. The budget is the step's `timeout_ms` (default 10 s), which is now valid with `settled` on any action. When it runs out the step halts with `[page never settled: ...]` and a message naming what was still moving (fonts, N images, layout); `optional: true` skips it. It replaces the chains of `wait` steps authors used for late font swaps and images. `lint` R014 (info) notes a `wait` step that only sleeps and points at `settled`; `diagnose` suggests it; `export playwright` emits a network-idle plus `document.fonts.ready` wait.
- **`docsxai burn`.** `docsxai burn <workspace-dir> [--flow <name>] [--out <dir>] [--report <file>] [--no-connector-outline]` bakes annotations into PNG copies from the one CLI, where it was only `docsxai-viewer burn`. It runs the viewer's `burn` through the same bin resolution as `render`, so the engine still does not depend on `@docsxai/viewer`; `--flow` can repeat. Exit 1 when the workspace has no `docs/` directory, 2 on a bad flag. The `docsxai` meta-package bin now points `DOCSX_VIEWER_BIN` at the viewer it depends on when the variable is unset, so `render` and `burn` also work in nested installs (pnpm, workspace checkouts) where the engine cannot see its sibling.

- **`hide` and `show` steps.** `action: hide` sets `visibility: hidden !important` on every element its `target` matches, for the rest of the flow or until a `show` (no target lifts every `hide`; a target lifts the `hide` that used the same selector). The element keeps its box, so nothing around it reflows, and it is absent from every later screenshot, halt shots included, and hidden from the next check at once even on a page whose reduced-motion reset gives every element a tiny `transition-duration` (the rule carries `transition: none`). The driver marks the elements with a data attribute and adopts a fixed engine-owned stylesheet keyed on it, on the element's own root, so it reaches shadow trees and is not blocked by a page's CSP; the selector is only data. The driver re-marks before each screenshot, so the hiding survives navigations and re-renders. `hide` waits for a match to exist and halts if none does, unless `optional: true`. That covers the Next.js dev overlay badge (`target: nextjs-portal`); there is no general CSS-injection step and no `display: none` option (it would reflow the page). `export playwright` emits both steps.
- **Per-step `timeout_ms`.** Any step that waits on a `target` (and a `wait` step's `wait_for: { selector }`) accepts `timeout_ms`, 100 to 30000. Unset, nothing changes: the default stays Playwright's 30 s for optional and non-optional steps alike, so existing flows run as before. Set it on an optional step and a missing target is skipped in that budget instead of 30 s. Rejected on steps where it would bound nothing.
- **Lint and diagnose.** R011 (info): `optional` step with no `timeout_ms`. R012 (error): `hide` without a `target`. R013 (warning): a step targets, anchors an annotation to, or waits on an element an earlier `hide` hid. `diagnose` adds hints for a halted `hide`, for a target hidden by an earlier step, and suggests `optional` + a short `timeout_ms` on `not-found`.

- **Burned callouts on small screenshots.** On annotation records with `obstacles`, the callout is at most `min(280, 0.62 x image width)` wide, never under 168 px (242 px on a 390 px screenshot), and when that box has no clear spot the burner tries two narrower ones before settling for the least overlap. Screenshots 452 px and wider, and records without `obstacles`, keep the fixed 280 px and burn to the same bytes as before.
- **`placement` on annotations.** `docsxai/annotations@1` records and flow-file step annotations accept an optional `placement` object, still valid without it: `inside` (callout inside a target big enough to hold it, no arrow), `side` (try only that side; `arrow` stays a soft hint whose corner half is ignored), `align` (`start`, `center`, `end` along the edge), `pin_arrow` (`nudge` moves only the callout, the arrow stays on the target), `max_width` (120 to 560), and `obstacle_radius` (0 to 2000 CSS px) and `obstacle_limit` (1 to 40), which `docsxai run` uses for that annotation's obstacle scan instead of 320 px and 40 boxes. Bounded and strict like `obstacles`. The interactive viewer ignores it.
- **`docsxai-viewer burn --report <file>`.** Writes `docsxai/burn-report@1` JSON: per annotation the callout and badge boxes, the px² still covering `obstacles` and other halos, badges and callouts, the overlap as a share of the callout's area, and `unplaceable: true` when that share is above 0.1 (`--max-overlap <ratio>`). The burner still draws every annotation; the pipeline decides what to drop. `burnFlow` returns the same report, `renderBurn` returns it with the PNG.
- **`docsxai run --verify-determinism`.** `docsxai run <workspace-dir> --verify-determinism [--runs <2-5>] [--format json|md|text]` runs the selected flows 2 to 5 times (default 2), each into its own root under `<workspace>/.docsxai-verify/run-<k>/`, and byte-compares every artefact: `annotations.json`, screenshots, step markdown, locators and halt context. The report (`docsxai/verify-determinism@1`, no timestamps or paths, deterministic order) names the first differing artefact by path with a cause: the JSON key path, the changed-pixel count and bounding box of a PNG (the pixel diff `docsxai diff` uses), the first differing text line, or the sizes. Exit 0 identical, 1 differing or a flow halted, 2 bad flags (`--runs` outside 2 to 5, or any of `--pause`, `--stop-after`, `--start-from`, `--cdp`). The workspace output is written only when every run agrees (run 1's files are copied in); otherwise it is untouched. The run roots are removed at the end by their listing, with no recursive delete. Report on stdout, progress on stderr. `PlaywrightSessionOptions` gains an optional `outputRoot`, and `run`'s flow loop moves to `run-flows.ts` unchanged for a plain run. The engine exports `compareRuns`, `compareArtefactBytes` and the report formatters.
- **Nightly drift recipes.** `docs/ci-recipes.md` gains copy-paste nightly jobs for GitHub Actions (schedule and `workflow_dispatch`), GitLab CI (pipeline schedule) and Woodpecker (cron): install, `run --verify-determinism`, `diff --against <baseline> --fail-on fail`, and the markdown reports uploaded as an artifact. Runnable copies sit in `examples/ci/` (not wired into this repository's own CI), and a test checks that they parse, that every command and flag they use appears in `docsxai --help`, and that the copies in the guide match the files. The page says browser capture must not run in per-PR pipelines on shared runners. A new guide, Determinism and drift, covers reading the report and fixing what varies.
- **Deprecation helper.** `deprecation.ts` prints `docsxai: <item> is deprecated since <version>, use <replacement>` once per invocation and looks names up in a retired registry (`warnDeprecated`, `findRetired`). Its first use is the retired `drift` command.
- **`login --oauth` and `inspect --ignore-https-errors` in `--help`.** Both already worked; the usage text, the CLI reference and the contract snapshot now carry them.
- **Project `app_url`.** The backend `Project` resource gains an optional `app_url`: the base URL of the running app the project documents, an absolute `http:` or `https:` URL of at most 2048 characters with no embedded credentials. `POST /v1/workspaces/:ws/projects` takes `{ name, app_url? }`, the new `PUT /v1/workspaces/:ws/projects/:project` takes `{ app_url: string | null }` (null clears it), and an invalid value gets `400 bad_request` naming `app_url`. `BackendStore` gains `setProjectAppUrl` and `createProject` an optional third argument; `MemoryStore` and `FsStore` implement both, and existing `meta.json` files read as before. A webhook run writes it into the materialised `.docsxai.json` as `app_url`, which is what `docsxai run` uses as the base URL for relative `navigate` values. This extends the frozen backend core additively: the `backend-api` contract snapshot gains the route and the optional member, no existing field or route changes.

### Changed

- **Backend core surface (`API-01`, `API-04`).** The frozen route list grows from 16 to 17 routes (`PUT /v1/workspaces/:ws/projects/:project`) and `Project` gains the optional `app_url`. Both are additive; `docs/public-surface.md` and the website reference list them.
- **Driver contract (`settled`).** `BrowserDriver` gains an optional `waitForSettled?(timeoutMs?)`. Optional, so existing third-party drivers (browxai included) keep compiling; a `wait_for: settled` step on a driver without it halts with a message saying so. `PlaywrightDriver` implements it.
- **Driver contract.** `BrowserDriver` gains two optional methods, `hideElements?(selector, timeoutMs?)` and `showElements?(selector | null)`; `nearbyBoxes` (from `0.2.1-rc.1`) becomes optional too. A `hide` or `show` step on a driver without the method halts with a message naming it, and so does an annotated step when `annotations.obstacles` is on and the driver has no `nearbyBoxes`. Seven existing signatures widen with an optional trailing `timeoutMs`: `click`, `fill`, `upload`, `press`, `hover`, `selectOption` and `setChecked`. `PlaywrightDriver` implements all of it; third-party drivers may ignore `timeoutMs` until they want the per-step budget, and add the optional methods when a flow needs them.
- **Burned badges keep off the target's text and its neighbours.** On annotation records with `obstacles`, `docsxai-viewer burn` now places the numbered badge at the corner of the halo, up to 26 px out, that covers the least of the obstacles, other halos and callouts, and of the target's own box. A flush-text target (a title, a tab, a list row) no longer loses its first letter under the badge. Callouts keep clear of the badge where it landed. Records without `obstacles` burn byte-identically to before; the same input still yields identical bytes.
- **Burned arrows and stems stay visible on dark screenshots.** `docsxai-viewer burn` reads the screenshot's pixels and, where at least a third of those under an annotation's arrow and stem are dark (integer luma under 110), paints a 2 px white outline under the near-black connector. 72 of 144 remotxai images and every trackxai image have dark UIs where the ink arrow was close to invisible. On light screenshots nothing changes: the tree and the PNG bytes are those of before, and the frozen legacy fixtures still hold. The callout box, halo and badge are untouched, and the same input still yields identical bytes. `--no-connector-outline` (CLI) and `connector: "off"` (`BurnOptions`, `burnFlow`) keep plain ink everywhere; there is no new annotation or schema field.

### Deprecated

- **`docsxai drift`.** Replaced by `docsxai pack --check` before it shipped in a release. It still works: it prints a deprecation warning (since 0.3.0) and runs `pack --check` with the same arguments, and it is not listed in `--help`.

### Security

- **Flow names are path-safe.** `name` (and `extends`) in a flow-file must start with a letter or digit, use only letters, digits, `.`, `_` and `-`, contain no `..` and be at most 64 characters, and `calibrate --name` follows the same rule. Before, `../.docsxai.json` passed the schema, and `run` or `run --verify-determinism` would then write under that path. A flow-file with a name outside the rule now fails to parse; uppercase letters, underscores and dots are still fine.
- **`run --verify-determinism` refuses symlinks.** A symlink in a run root stops the verification before anything is copied into the workspace, with the entry named.
- **Verify reports carry no absolute paths.** Halt messages in the report are cut to their first line and every absolute path (POSIX, Windows, UNC, `file://`) becomes `<path>`, as the report header always claimed.
- **Verify comparison is bounded.** Artefacts above 64 MiB are compared by size and then byte by byte in 1 MiB chunks, and reported as a `bytes` difference, instead of being read into memory twice.
- **`docsxai pack` checks the optimiser.** The output of `oxipng` (or whatever `DOCSX_OXIPNG_BIN` names) has to be a complete PNG with the same pixels as its input. A binary that exits non-zero, writes garbage or is lossy stops the build and is never hashed.
- **More pack guards.** Titles, captions, alt text and callouts that hold a private-network address (10/8, 172.16/12, 192.168/16, 169.254/16), an email address outside the reserved example domains, an `Authorization:` header that is not `Bearer`, or a token in a URL query (`?token=`, `key=`, `sig=`, `signature=`, `access_token=`, `api_key=`) stop the build.

### Fixed

- **Hardening from the pack review.** `pull` checks every file name in a backend response before it writes anything and refuses the whole response on one bad name (a flow file must be `<flow name>.flow.yaml`, annotations and screenshots must sit under `docs/<flow>[/<variant>]/`). `pack --check --against` and the raw and workspace pack readers refuse symlinked PNGs and PNGs over 64 MiB, and a file that is not JSON no longer has its text quoted in the error. The `run --verify-determinism` report scrubs a path under `/tmp`, the home or temp directory or the workspace root to the end of its token run, spaces and single segments included. A flow name may not end in `.` or be a Windows device name (`con`, `nul`, `com1` and so on), and `run` and `pack` refuse two names that differ only by case.
- **Backend `app_url` target filter and review follow-ups.** The backend refuses a project `app_url` whose host is link-local or a cloud-metadata address (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `100.100.100.200`, `metadata.google.internal`, `instance-data`, in decimal, hex, octal, IPv4-mapped and trailing-dot forms) on `POST`/`PUT` and again when a run writes `.docsxai.json`; the new `DOCSX_BACKEND_DENY_PRIVATE_APP_URL=1` also refuses loopback, RFC 1918, CGNAT and unique-local hosts (listed in `doctor`, `docs/public-surface.md` ENV-10). - **Review fixes for the hardening and SharePoint work.** `@docsxai/plugin-sharepoint` takes `graph_base_url` only as `https` on `graph.microsoft.com`, `graph.microsoft.us`, `microsoftgraph.chinacloudapi.cn` or `graph.microsoft.de` (loopback `http` only through the `createSharePointPublisher({ allowLoopbackHttp: true })` test option), never follows a redirect, refuses an attachment path outside the workspace and hashes the bytes it read, refuses `.`/`..` file names and folder segments, drops invalid or off-host manifest entries and caps manifest (8 MiB) and JSON (1 MiB) reads; the viewer's `readRegularFile` refuses a FIFO before opening it and caps the bytes actually read; `pull` also refuses annotation and screenshot paths, and the directories they sit in, that differ only by case, and variant segments and screenshot stems that are Windows device names or end in a dot; `verify-determinism` also scrubs a capitalised directory with a space (`/Users/me/My Projects`) under a known root.
- **Backend webhook runner writes a workspace the engine can run.** `SpawnRunner.materializeWorkspace` wrote each artifact slot as `<slot>.json` (`flows.json`, `annotations.json`, ...) in the temp dir, a layout `docsxai run` cannot read: it lists `flows/*.flow.yaml` and exits with `has no flows/ directory`. It now writes `flows/<name>.flow.yaml`, `docs/<flow>[/<variant>]/annotations.json`, the screenshot bytes from the blob store under `docs/<flow>[/<variant>]/screenshots/`, `docs/style.yaml`, `docs/style.json`, `docs/locators.yaml` and `.docsxai.json` (`app_url` comes from the project's `app_url`, below), the same layout `pull` produces. - **`docsxai doctor` knows `DOCSX_OXIPNG_BIN`.** The variable `docsxai pack` reads to find `oxipng` was missing from the doctor's list of `DOCSX_*` names, so setting it was flagged as a likely typo.

## [0.2.0] - 2026-06-26

The MVP: an LLM-agnostic engine + Claude Code plugin that walks a web app, follows written flows, and emits screenshot-rich docs. Calibration is AI-assisted and rare; execution is deterministic, agent-free, and CI-friendly.

### Added

#### Bare `docsxai` meta-package

- **`docsxai` on npm is the batteries-included CLI package.** `packages/docsxai/` carries a `bin.mjs` that resolves `@docsxai/engine`'s CLI entry (new `@docsxai/engine/cli` export) and runs it **in-process** (no spawn), plus `index.mjs`/`index.d.mts` re-exporting the engine's library surface. #### Engine — `docsxai doctor`

- **`docsxai doctor [<workspace-dir>]`** — environment + workspace health-check: ✓/✗ checklist with a one-line fix per failing row (− rows are informational; exit 1 on any ✗). Checks: Node >= 20; Chromium presence for playwright-core (the documented one-shot install as the fix); `.docsxai.json` found + parseable (cwd or the arg; informational when absent); every flow-file parses (count; first error fails); auth descriptor parse + cached-session freshness (expired → `capture-auth` fix hint); backend reachability via `GET /v1/health` when `backend_url` is configured (with a token-presence note); the plugin declarations through the same stage-1 inspection `plugins list` runs — declared/installed/lock/capabilities, **no plugin code executed**; viewer-bin resolution naming which of the three layers hit; and `DOCSX_*` env sanity (`DOCSX_CACHE_KEY` well-formed when set; unknown `DOCSX_*` names flagged as likely typos).

Zero YAML in user repos — config lives in the backend.
- **Run dispatch** — per-project serial `QueuedDispatcher` → `SpawnRunner`: materializes the configured revision into a temp workspace, runs the engine CLI, appends run history.
- **Output strategies** — `pr-comment` (GitHub REST comment with the run/drift summary), `viewer-refresh` (re-render recorded as a content-addressed blob), `wiki-push` (the project's configured publisher plugin via the engine plugin runtime). App registration, webhook URL/secret, and installation tokens are owner-gated (checklist in the backend README).

#### Backend — persistence, blobs, OAuth, encrypted cache (`@docsxai/backend`)

- **Filesystem persistence** — `FsStore` behind the new `BackendStore` interface (atomic tmp+rename writes, traversal-guarded paths), selected via `--data-dir` / `DOCSX_DATA_DIR`; the in-memory store remains the default for tests.
- **Content-addressed blobs** — `POST/GET/HEAD /v1/blobs` (sha256-addressed, deduplicated) with 10 MB JSON / 25 MB blob body limits (413). Screenshots travel as `docsxai/screenshots@2` sha256 manifests; the engine HEAD-probes, uploads, and integrity-verifies on pull (base64 payloads are gone).
- **Revision finalisation** — `POST …/revisions/:rev/finalize`; artifact PUTs afterwards are rejected 409 (`revision-finalized`); `docsxai push` finalizes — linear-immutable is now enforced, not aspirational.
- **OAuth 2.1 + PKCE** — S256-only authorization-code flow with single-use 5-minute codes, refresh-token rotation, sha256-hashed token storage; CI keeps the `DOCSX_TOKEN` bearer path. `docsxai login --oauth` runs the loopback handshake and stores tokens at `.auth/backend-token.json` (0600) with auto-refresh.
- **Encrypted storage-state relay** — `PUT/GET/DELETE /v1/workspaces/:ws/auth-cache/:role` stores client-side AES-256-GCM envelopes (`BackendStateCache`, key from `DOCSX_CACHE_KEY`); the backend never sees plaintext session state.
- **Run history wired** — `docsxai run` appends execution records to backend-bound workspaces (offline-tolerant).

#### Viewer — burn renderer + hardening (`@docsxai/viewer`)

- **`burn` — durable burned annotations** — browser-free Satori → resvg pipeline bakes halo/badge/callout/arrow onto screenshot copies (`docs/<flow>/burned/`), byte-deterministic, positioned by the same `placeCallout` as the interactive viewer; vendored Inter (OFL-1.1). The static-delivery path for Confluence/Notion-class surfaces.
- **Single-sourced overlay** — the inline viewer script is bundled at build from `overlay-runtime.ts` importing the real `placeCallout`; the hand-maintained ES5 port is gone.
- **CSP + safe markdown** — every emitted page carries `default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; script-src 'unsafe-inline'` (zero network egress), and step write-ups render through micromark in safe mode instead of `<pre>`.
