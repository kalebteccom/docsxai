# Changelog

All notable changes to this project. Format loosely follows [Keep a Changelog](https://keepachangelog.com/); this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Public copy lint: `packages/engine/test/public-copy-lint.test.ts`.** Fails on environment-variable-like tokens, internal hostnames, private IPs, `/srv` paths and ticket or spec ids (`DOC-`, `CLI-`, `PACK-` and kin) in the landing and getting-started pages, `llms.txt`, the viewer's emitted UI (en and es) and the string literals of CLI and MCP errors and help, read with the TypeScript parser. Documented `DOCSX_*` names are allowed in CLI and MCP messages only. A second pass over mirrored docs, this changelog and package READMEs reports secret names, hosting providers, server paths and `docs/ai-context` pointers without failing
- **`docsxai run --device-scale-factor <1-4>` captures at 2x or more.** Also read from `DOCSX_DEVICE_SCALE_FACTOR` when the flag is absent; default 1 leaves output byte-identical. `annotations.json` gets `device_scale_factor` above 1, its boxes and obstacles are in the PNG's device pixels, and `docsxai burn` takes its pixel ratio from the file
- **`scripts/burn-trackxai.mjs --dpr` burns 2x captures; the viewer burn takes `pixelRatio`.** Raws in device pixels (ratio from `--dpr`, the sidecar's `device_scale_factor`, or PNG width over file-name width) burn with `display_width` in CSS px, so `scale: "auto"` gives 2.33 at 2560 px and 2.23 at 780 px. The phone header, bottom nav and floating button bands, side margins, text floors and the pixel text search scale with the ratio, and manifest entries keep `width` and `height` in CSS px and add `png_width` and `png_height`
- **`docsxai-viewer <command> --help` and `-h` print that command's usage.** `build`, `burn`, `site` and `pack` show their usage lines and flag notes and exit 0, as `docsxai help <command>` does; `docsxai-viewer --help` and `-h` print the full help and exit 0. An unknown flag still exits 2
- **`scripts/burn-trackxai.mjs --webp` writes a lossless WebP twin beside each new PNG.** It runs `cwebp -lossless -z 9`, keeps a twin only when it is under 100 kB and smaller than the PNG, and prints a warning with both sizes when it drops one. Without `cwebp` on `PATH` it stops with an install hint
- **Landing page "What it makes" section.** docsxai.dev shows two product shots after the hero: a trackxai capture raw and burned with a caption theme, and the lines `docsxai run` prints for a matrix flow. Each comes in dark and light, follows the site's theme, sends 2x files (780 px, shown at 390 CSS px) to phones and has a lossless WebP twin under 100 kB. The terminal shot is composed from the engine's output format and the real trackxai flow counts, not a recorded session, and prints shorter lines at 390. `node scripts/landing-showcase.mjs --raw <dir> --out website/public/showcase` redraws them with satori and resvg and writes the manifest the page reads

- **`scripts/layout-audit.mjs --mode states` checks that status lines never shift layout.** For each element in the config's `states` list it loads the page once per state (idle, pending, slow, failed, done), runs that state's steps and fails when the element's top or height moves by more than 1 px. `scripts/layout-audit.states.json` covers the copy buttons and the screenshot error line.

### Changed

- **Themed burns route the line connector around text.** When a caption is clear but its line crosses an obstacle, another halo, badge or caption, the burner moves the caption to the spot with the shortest straight line that crosses nothing (a clean hinted side wins), else draws the line with one right-angle elbow, else keeps the spot it had. `caption_style: "auto"` keeps a caption it can route. The burn report gains `route` (`straight`, `elbow`, `none`) and `connector_crossings` for line burns. Burns without a theme keep their bytes. Guide: `docs/annotation-placement.md`, Routing the line.
- **docsxai.dev serves `/showcase/*` with a one-year immutable `Cache-Control`.** The landing images are hash-named, so `netlify.toml` caches them like `/_astro/*`; a test checks the rule and that `public/showcase` holds only hash-named images plus `manifest.json`.
- **Landing hero flow diagram: the muted `expect toast` line meets 4.5:1 in both themes.** `.dxf-flow code.muted` goes from opacity 0.6 to 0.85 (dark 4.35:1 and light 3.55:1 before, light bold part 2.84:1); `check-flow-contrast.test.mjs` computes the pairs.
- **Guide: themed caption packs.** `docs/themed-caption-packs.md` (also on docsxai.dev) takes raw captures from `docsxai run` to hash-named PNGs, lossless WebP twins and a screens-pack manifest with a light and a dark tokens file, then covers sizes per width class (`scale: "auto"`, `display_width` with `narrow_below`), `connector_style` and `caption_style` with the rule for the badge fallback and the legend it needs, reading the burn report and `scripts/burn-probe.mjs`, a no-overlap test a project can copy, and a worked example with the `examples/burn-theme/` trackxai pair.
- **`scripts/burn-probe-batch.mjs` checks a whole folder of raw captures.** It burns every frame of a flat (`<screen>.<locale>.<theme>.<width>.png`) or rawcap (`<flow>/<step>/<locale>.<theme>.<viewport>.png`) folder with the trackxai tokens, writes the burned PNGs to `<out>/previews/` and a `report.md` with one row per annotation (mode, side, connector length, caption over text and over the phone header and nav, connector crossing text, badge next to its target, OK or CHECK), CHECK rows first. Repo script, not in the npm packages. Guide: `docs/burn-theming.md`, Checking a whole capture folder.
- **remotxai caption tokens and `burn-probe-batch.mjs --project`.** `examples/burn-theme/remotxai-light.tokens.json` and `remotxai-dark.tokens.json` carry the remotxai docs look (17 px text, `display_width` 800, 390 under 900 px). `--project trackxai|remotxai` picks the probe's default tokens, and `--tokens-dark` and `--tokens-light` still override. Guide: `docs/burn-theming.md`.
- **Landing page first-run section.** docsxai.dev gains a "First run" section after Install: `init --app-url`, `doctor`, calibrate through the Claude Code plugin with an example request, `run`, and `render` to open the viewer, each with a copy button and one line of expected output, then a link to the quickstart. The page now names the `readable` preset, the second `display_width` for narrow captures, `--lang` and `pnpm setup` for a pnpm global install.
- **Themed burns join callouts to targets with a thin line.** With a `burn.theme`, the connector is one 2 px line (multiplied by `scale`) from the caption edge nearest the target to the target's edge, ending in a small dot. It replaces the triangle and stem, and the white outline over dark pixels. The line takes `callout_border_color` (`ink` without an outline) and switches to the callout's text or fill colour where that is under 3:1 against the pixels under it. The halo ring moves 3 px outside the target and the badge sits off its corner, so neither covers text in the target. Text found in the screenshot pixels joins the annotation's `obstacles`, and a caption that would cover text moves up to 176 px out, or docks along the top or bottom edge, with a longer line. A caption covers no text when any clear spot exists, trying a one-line wide box and one text step smaller first. Badges sit at the target's corner, off text. Portrait phone captures keep captions and badges off the header, bottom nav and floating button. New key `caption_style` (`full`, `badge`, `auto`): `badge` draws only the numbered badge and ring, `auto` falls back to it where no caption spot is clear, or where the connector would cross text, and marks it in the burn report. New key `connector_style` (token `shape.connector`): `auto` (default: the line with a theme, the triangle without), `line`, `chevron` (an open chevron at the target) or `arrow` (the triangle and stem as before). `arrow_style` still picks the side. Burns without a theme keep their bytes. Sample: `node scripts/burn-trackxai-sample.mjs` with the `examples/burn-theme/trackxai-*.tokens.json` pair. Guide: `docs/burn-theming.md`, Connectors.
- **Themed burns with `connector_style: "arrow"` paint the arrow and stem in the callout's fill on dark screenshots.** With a `burn.theme`, a triangle connector over dark pixels is drawn solid in `callout_background`, so it reads as the callout's tail. The dark-ink-with-white-outline look stays where a tenth or more of the pixels under it match the fill, and for burns without a theme, which keep their bytes. A light connector on light pixels mirrors this with a dark callout fill.
- **Themed burns balance callout lines.** With a `burn.theme`, a callout keeps the number of lines the plain wrap gives and narrows to the smallest width that holds them, so no line ends with one word left over. A one-letter word (Spanish `a`, `y`, `o`) and the list number stay with the word after them, and a path or URL wider than the line breaks after `/`, `-`, `_`, `.` or `:`. Burns without a theme wrap as before.
- **Plugin and vendored skill text matches the CLI.** `/docsxai:run` names the `flow variants` and single `flow` forms of the summary line and the indented `next:` lines, `/docsxai:render` and `calibrate` say `render` has no language flag and point at `docsxai-viewer build` and `site` with `--lang`, `/docsxai:doctor` names `--offline`, `/docsxai:login` shows its `login: ok.` line, `/docsxai:export` notes that `--out` applies to `adf` too, `/docsxai:pull` lists matrix variant paths, and `calibrate` drops a pointer to a step that does not exist, adds `wait_for: load`, `copy_by_locale`, the two-width `display_width` form and an accurate `init` next-step list. `diagnose` covers a target hidden by an earlier `hide` step. The plugin tests now pin the MCP tool list, the `burn.theme` numbers, the `--lang` claims and the summary line wording against the source.
- **Docs: burn report keys `route` and `connector_crossings`, the `--badge-only` flag, and `device_scale_factor` as the burn pixel ratio are documented.** The burn and annotation guides cover them, and `AGENTS.md` states the `--testTimeout=30000` rule for test scripts.

### Fixed

- **A screenshot that fails to load no longer moves the page.** In the viewer and the Starlight site, the error line and its Retry button now sit inside the screenshot's box, and the box keeps its size when the file fails, so failing, retrying and loading again leave every step where it was. Before, the line was inserted under the image and a broken image could shrink to a line of text.
- **Copy buttons run one copy at a time.** The viewer, the Starlight site and docsxai.dev ignore a click while a copy is still pending. On docsxai.dev the "Ctrl+C" fallback label has its own slot beside "Copy" and "Copied", so no state changes the button's size.
- **`renderBurn` rejects a `pixelRatio` outside 1 to 4.** `0` with `scale: "auto"` ended in `Invalid typed array length: Infinity`, and `NaN` or a negative ratio burned at a wrong size without a word; each now throws `pixelRatio must be a number from 1 to 4`.
- **`scripts/burn-probe-batch.mjs` burns 2x raw captures at their device scale.** A frame whose sidecar has `device_scale_factor`, or whose PNG is exactly 2 to 4 times its file-name width, now burns, picks `caption_style` and checks phone chrome in device pixels; before, the probe drew every frame at 1x and graded 2x captures wrongly. An out-of-range `device_scale_factor` fails that frame.
- **`docsxai-viewer build|burn|site` read `--flag=value`, and reject an empty or repeated value.** `--flow=a` was an unknown flag, `--out ""` and `--max-overlap ""` fell back to their defaults, and a second `--out` or `--title` silently won. `--flow` still repeats.
- **`docsxai-viewer pack` burns 2x captures at their device scale.** A workspace `annotations.json` with `device_scale_factor`, or a raw capture sidecar with the same key, now reaches the burner as its pixel ratio, as `burn` already did; before, pack drew captions at 1x size on a 2x screenshot. A value outside 1 to 4 stops the pack and names the file.
- **`docsxai run` rejects an empty value for its value flags.** `--flow ""`, `--variant ""`, `--stop-after ""`, `--start-from ""` and `--cdp ""` were read as unset and ran every flow or variant; they now exit 2 with `needs a value`.
- **`docsxai run --start-from` no longer merges steps captured at another device scale.** Earlier steps in an `annotations.json` recorded at a different `--device-scale-factor` (absent counts as 1) are dropped with a warning, since their boxes are in other pixels than the re-run steps and the file has one `device_scale_factor`.
- **Quickstart flow passes `docsxai lint` with exit 0.** Its annotation names `target: $nav_reports`, so lint no longer warns R002 and exits 1 on the page's own example, and the sample `run` lines match what `run` prints (`run: open-reports, starting`).
- **Landing page fits 320 and 360 px phones and 200% text.** The hero's run transcript wraps its last column under 34rem, where it scrolled sideways, and the feature cards drop to one column when 15rem is wider than the screen.
- **Install docs no longer say `docsxai` puts `docsxai-viewer` on your path.** A global npm or pnpm install links only the `docsxai` bin. `render` and `burn` still work; the docs now say to add `@docsxai/viewer@next` to call `docsxai-viewer` directly, for example with `--lang es`.
- **Spanish viewer and site text reviewed.** Instructions now use tú imperatives ("Pulsa Ctrl+C", "Comprueba tu conexión") with one term per concept (captura, paso, flujo, anotación, ID), "registro de anotación" becomes "anotación", and a term table in `ui-strings.test.ts` pins them
- **`docsxai run` accepts `file://` URLs again.** The URL check added for `--base-url` and `app_url` refused `file://`, which broke runs against a local static site. `run` takes `http://`, `https://` and `file://`; `ftp:`, `javascript:`, `data:`, `mailto:` and garbage still exit 2 (`--base-url`) or 1 (`app_url`). `init --app-url` and `login --backend-url` stay `http(s)` only.
- **Landing page and burn theming guide no longer name `0.3.0-rc.4` as the installable prerelease.** The install note and the CLI card said `docsxai@next` is `0.3.0-rc.4`, and the availability note on the burn theming guide said `burn.theme` is available from it through `docsxai@next`; `next` is `0.3.0-rc.3`, as the README and Installation page say. They now name `0.3.0-rc.3` for `next` and say `burn.theme` is new in the next release. New tests load every `burn` block in `docs/burn-theming.md` and the burn-theme example through the real theme loader, validate the manifest in `docs/pack-manifest.md`, parse the flow files in the README, quickstart and flow-file reference, and check the `docsxai` commands and flags of the guides and example READMEs against `docsxai --help`.
- **Burn help and guides match the code.** `docsxai burn --help` and `docsxai-viewer burn --help` say that `--no-connector-outline` skips reading the screenshot's pixels, so a themed line keeps the callout's outline colour and no text is estimated, and that `burn.theme` sets the look. The theming guide covers `caption_style`, the clean halo and badge and the phone chrome numbers, and gives the auto factor of a 780 px capture at the default `display_width` as 1.09 (it said 1.08). The landing page no longer says `docsxai@next` is `0.3.0-rc.4`.
- **A side hint no longer pulls a short callout onto a neighbour.** The bonus `arrow_style` or `placement.side` gives its side now outweighs at most a 2 px strip of content along the callout's width. A 60 px label on a phone screenshot used to keep its hinted side over 6 px of a neighbouring control. Callouts 200 px wide or more score as before.
- **`plugins sync` with three plugins on one namespace.** It locked the last of them and named only the second as not locked. It now locks none of them and names every claimant.
- **Two flow files with one `name:`.** `run` started both and let them overwrite one `docs/<name>/`, and `lint` and `flow-tree` kept only the last. All three now stop with exit 1 and name both files.
- **A value flag given with no value.** `init --app-url`, `inspect --url`, `lint --flow`, `export adf --out`, `zip --out`, `push --kind` and `pull --rev` (and the other value flags of those commands, `calibrate`, `diagnose`, `style`, `flow-tree`, `capture-auth` and `plugins`) silently fell back to their default, so `export adf --flow` exported every flow. They now exit 2 with `<flag> needs a value`. `inspect --wait soon` and `init --persist disk` exit 2 too, where they used to wait 0 ms and scaffold into the given directory.
- **Matrix viewport names `screenshots`, `halts` and Windows device names.** A viewport named `screenshots` or `con` made a variant directory that `pull` refuses and Windows cannot create. The flow-file parser now rejects `screenshots`, `halts`, `con`, `prn`, `aux`, `nul`, `com1` to `com9` and `lpt1` to `lpt9` as viewport names.
- **Session cache files.** Roles `a/b` and `a_b` shared `.auth/a_b.json`, so one role ran with the other's session, and a role named `backend-token` overwrote the OAuth token file. A role with characters outside `A-Za-z0-9_.-`, and `backend-token`, now gets a hash suffix in its file name (an existing cache for such a role is re-captured once). The cache file is also written with mode 0600; it was group-readable under a default umask.
- **`style` on a path that does not exist.** A mistyped workspace path got a new `docs/style.yaml` tree created under it and exit 0. `style` now exits 1 with `<path> is not a directory` and writes nothing.
- **`push` with a doc pack it cannot read.** An invalid `docs/style.json` made `push` throw after it had created a backend workspace, a project and an unfinalized revision. It now reads the pack first, exits 1 naming the file, and touches the backend only when the pack reads. The `.docsxai.json` that records the backend ids is written atomically.
- **`pull` with an unknown artifact name in a revision.** The names a backend listed went into the request path as they came, so `../../x` reached another endpoint with the bearer token. `pull` now requests only `flows`, `annotations`, `screenshots`, `style` and `locators`, and prints a warning for any other name.
- **`zip` followed symlinks in its fixed entries.** `README.md`, `.docsxai.json`, `auth/strategy.yaml` or `docs/` linked to a file or directory outside the workspace went into the archive with the target's content; only entries found below a directory were checked. All entries get the check now. `zip` also creates the output directory only after it has something to write, and writes the archive atomically.
- **`push` read files behind symlinks.** A flow file, annotations file, screenshot, `style.yaml`, `style.json` or `locators.yaml` that was a symlink to a file outside the workspace was read and sent to the backend. Those files are now left out of the pack.
- **`pack --check --threshold ""`.** An empty or blank threshold passed as 0 percent. It now exits 2 like any other value that is not a percentage of 0 or more.
- **`docsxai-backend` answers 400 to a request target the URL parser rejects.** A request line such as `GET //` or `GET //[` returned a 500 with `Invalid URL`; it now returns a JSON `bad_request`.
- **Webhook run history records the revision that ran and the runs that never started.** A `head` revision that moved while the engine ran was recorded as the newer head, and a job whose payloads could not be laid out left no row. The row now names the revision the run executed against, and a failed materialization appends a failed run with the reason.
- **Webhook repo matching ignores case.** A delivery whose `owner/name` differs only by case from the configured repo got a 404, because GitHub treats the name case-insensitively. Both stores now match it.
- **`FsStore` lists projects in creation order.** It listed them, and picked the project for a webhook repo, in id order; `MemoryStore` used creation order. Both stores now agree.
- **Docs site at 390 px, round two.** Shell commands in code blocks wrap with an indented continuation line, where they used to scroll sideways, and the copy button still copies one command. The "On this page" dropdown links are 44 px tall. The landing diagram's 10 px labels grow to 12 px once the panels stack.
- **Installation and Quickstart match the CLI.** Installation describes doctor's `ok:`, `fail:` and `next:` lines. The Quickstart shows the starting line `run` prints for each flow, points at the `flows/example.flow.yaml.sample` that `init` writes and how `calibrate --from` turns it into a flow, uses `http://localhost:3000`, and says a callout opens on hover, tap or Tab.
- **`docsxai doctor` usage lists `--offline`.** The `Usage:` line in `docsxai --help`, `docsxai help doctor` and the CLI reference now show `docsxai doctor [<workspace-dir>] [--offline]`, the flag the handler already read. A new test pins the flags of every command against its usage text, its `help` screen and the flags its handler reads, so a flag added to one without the other fails the suite. The header comment of `docsxai-viewer` lists the flags its usage text shows.
- **Unknown and repeated flags.** `run --flwo x` ran every flow, because a flag no command reads was ignored, and `--flow a --flow b` kept the last. `init`, `calibrate`, `inspect`, `run`, `lint`, `flow-tree`, `diagnose`, `style`, `zip`, `baseline`, `diff`, `export`, `plugins`, `login`, `push`, `pull`, `render` and `capture-auth` now exit 2 on a flag they do not take, with a `did you mean` when one is close, and on a flag given twice. `burn` and `pack` already did the first.
- **`run --pause <workspace>`.** The flag took the workspace as its value, so `run` reported a missing workspace. Flags that take no value (`--pause`, `--headed`, `--force`, `--check`, `--fresh`, `--headless`, `--ignore-https-errors`, `--include-viewer`) no longer read the next argument, and `--pause=yes` exits 2.
- **Flow name that differs from its file name.** `flows/payment.flow.yaml` with `name: checkout` ran fine, but `extends: payment` found nothing and the output went to `docs/checkout/`. `lint` now warns (R017) and names both. `run` is unchanged.
- **`pull` that failed partway.** `writeDocPack` wrote flows, then annotations, then screenshots one file at a time, so a disk error or a path in the way left a workspace holding part of the new revision and part of the old. Every file is now staged next to its target first and renamed into place together; a failure while staging changes nothing and a failed rename puts the swapped files back.
- **`export adf` and `export playwright` followed symlinks.** A flow file, step markdown file or screenshot that was a symlink to a file outside the workspace was read: its text went into `projection.json`, and its path into `attachments.json` for a publisher to upload. Those files are now left out, as `zip` and `push` do. A symlink to a file inside the workspace still works.
- **`doctor` with an unknown or repeated flag.** `doctor --ofline` ignored the flag and probed `app_url`. It now exits 2 on a flag it does not take, with a `did you mean` when one is close, on `--offline` given twice, and on `--offline=yes`.
- **`--cdp` connection left open.** Commands that attach to a running Chrome (`run`, `inspect`, `diagnose`, `capture-auth`) kept the CDP connection when setup failed after the connect (no context to create, no page to open, a refused binding), and `close()` dropped nothing. `inspect --headed --cdp` skipped the close altogether. The connection is now released on every exit path, once; a context that docsxai created in the attached Chrome is closed first, and the operator's own contexts and tabs are never touched. A `capture-auth` browser launched fresh is also closed when its first navigation fails.
- **`run --concurrency` lost results when one flow's cleanup threw.** A browser that failed to close, or a `--pause` wait that threw, rejected the whole worker pool: `run` ended with an unhandled error and no summary while the other workers kept writing. A close failure is now a warning on stderr, the browser is closed even when the pause wait throws, and any other throw that escapes a flow is recorded as that flow's failure, so every flow still gets its line in the summary.
- **Ctrl-C and SIGTERM during `render`, `burn` or `pack`.** The signal went to the viewer child and docsxai waited for it with no limit: a child that ignored the signal hung the command, a second Ctrl-C did nothing, and a child that exited 0 on the signal made docsxai exit 0 after printing `interrupted`. The child now gets SIGKILL 10 s after the first signal, a second signal ends docsxai at once with 130 or 143, and an exit 0 after a signal becomes 130 or 143.
- **`run --start-from` or `--stop-after` with a step id that does not exist.** The browser launched first and the run then ended as a failed flow, exit 1 with a `doctor` hint. Both flags now check the id against the selected flows before anything launches, exit 2 and list the steps the flow has. `--stop-after` still runs when at least one selected flow has the step.
- **Viewer links and images for names with `#`, `?` or `%`.** `docsxai render` percent-encodes these characters in the screenshot, flow-card, thumbnail and previous/next flow URLs. A step id such as `a#b` used to point at `a` and show a broken image.
- **`docsxai render --flow` with repeated or unknown names.** A flow named twice produced two pages and two index cards, and a name with no folder under `docs/` produced an empty page with no message. Each flow now renders once, and an unknown name is skipped with a warning.
- **`docsxai render` with a directory named like a screenshot.** A directory called `<step>.png` under `screenshots/` crashed the copy. The step now shows the missing-screenshot state.
- **`docsxai-viewer site` with a damaged `annotations.json`.** A file whose `annotations` is not a list, or a record whose `step` is not a string, crashed the emit. The site now warns with the same reasons `render` shows, skips the bad records and falls back to the screenshots. A directory named like a screenshot counts as a missing screenshot.
- **`docsxai-viewer site` builds with quotes, `&`, spaces, `#`, `?` and `%` in names.** A step id with `"` or `&` was written as a JSX string without escapes, so `astro build` failed to parse the page. A flow name with a space gave a page slug the sidebar did not link to, and an image named with `#`, `?` or `%` could not be imported. Such values are now passed as JavaScript strings, flow pages and images use a slug of letters, digits and hyphens (a second flow with the same slug gets `-2` and a warning), and the heading escapes `*`, `_`, `[`, `]`, `&` and `~`. Flow and step titles on the page keep the original names.
- **`docsxai-viewer site --build` explains a build that never ran.** A missing site directory was created as a side effect, and a build killed at the 10 minute limit or a process that could not start left `site: astro build failed` with nothing under it. Each case now prints its reason.
- **`docsxai render` and `docsxai-viewer site` warn about a missing `docs/` folder.** A mistyped path wrote an empty viewer or an empty site and exited 0 with no message. The empty page is still written, and the command now prints a warning naming the folder.
- **`docsxai-viewer site --title` with a blank value or a line break.** An empty or whitespace title produced an empty site title, and a title with a line break or other control character broke the page front matter. A blank title now falls back to `Documentation` and control characters become spaces.
- **`docsxai pack` guard scans `generated_for`.** The publish guard checked titles, captions, alt text and callout copy but not `--generated-for`, which lands in the public manifest. A token or email pasted there now stops the build like any other leak.
- **`docsxai-viewer site` with names that are not plain path parts.** A step id such as `../../x` or a flow name with `:` or `\` was joined into the output paths, so an image could land outside `src/assets/flows/`. These flows and steps are now skipped with a warning, the same rule `render` applies.
- **`docsxai-viewer site` warns instead of staying silent.** A `--flow` name the pack lacks, and a `docs/style.json` that is not valid JSON (its accent and logo were dropped without a word), now each produce a `site: warning:` line.
- **`--lang` with a language that has no text table warns.** `docsxai-viewer build --lang fr` and `docsxai-viewer site --lang fr` wrote English pages and said nothing. They now print a warning that only `en` and `es` have tables; the output is unchanged.
- **`docsxai-viewer build --flow <flow>` renders the variants of a matrix flow.** `burn --flow` already selected `<flow>/<variant>`, but `build --flow login` on a flow with only variant folders wrote an empty `login` page and none of the variants. `build` now selects them the same way, and a repeated `--flow` name burns once.
- **`docsxai-viewer site` says when it leaves matrix variants out.** A flow that ran a `matrix:` block keeps its output in `docs/<flow>/<variant>/`, which `render` shows and the site does not read. A pack of only matrix flows produced an empty site with no message, and `--flow <name>` for one reported a missing `annotations.json`. Both now print a warning that names the variant folders.
- **`docsxai-viewer site` removes pages of flows that left the pack.** Emitting into an existing site directory only added files, so a deleted flow or step kept its page and images, which Starlight still built and indexed for search. - **`docsxai pack` names the bad field in a damaged `annotations.json`.** A `bounding_box` with a string for `x`, a `placement.side` that is not a side, or a bad `nudge`, `obstacles`, `arrow_style` or `index` failed inside the burner with `inputValue.trim is not a function` or `Cannot read properties of undefined`. - **Copyable capture commands quote odd names.** The `docsxai run --flow ... --start-from ...` command that `render` and `docsxai-viewer site` offer for a missing screenshot was pasted as written, so a step id or flow name with a space, quote or `$` split into several shell words or ran as code. Such an annotation is now skipped with a warning that names its selector and step, and `burn --report` lists it with `skipped` set. A box that only overhangs an edge is clipped to the image.
- **`docsxai burn` no longer throws on a `nudge` with a NaN or infinite part.** Satori rejected a NaN position, and an infinite one drew the callout off the image. Such a part now counts as 0.
- **A viewport-only variant such as `<flow>/sm` no longer sets the page language.** `sm`, `md`, `lg`, `xl` and `xs` read as locale tags, so `docsxai-viewer build` and `site` ignored `--lang` for those flows. ### Added

- **Themeable burned captions (`burn.theme`) (#120).** The `burn.theme` block of `.docsxai.json` sets the look of the halo, numbered badge, callout and arrow that `docsxai burn` and `docsxai pack` draw, and of the interactive viewer's overlay, which reads the same values through `--sd-*` CSS variables. Keys: `accent`, `ink`, `callout_background`, `callout_border_color`, `callout_border_width`, `radius`, `shadow`, `badge_shape` (`circle`, `rounded`, `square`), `badge_fill`, `font_size`, `line_height`, `padding_x`, `padding_y` and `font` (a TTF or OTF inside the workspace; the bundled Inter without it). `preset` selects `clean`, `soft` or `high-contrast` and any key overrides it; `high-contrast` is black on white at 21:1. `from` names a tokens file (W3C design tokens, or a nested or flat map) and `tokens` maps theme keys to token paths; a mapped token the file lacks stops the command with the key and the path. A bad block lists every problem with its key, and text pairs under WCAG AA print a warning. A workspace without a block burns the same bytes as before, and a viewer page without one differs only in the stylesheet reading each value through a `var()` with today's value as the fallback. A light connector colour gets a dark outline over light pixels, mirroring the white one over dark pixels. Guide: `docs/burn-theming.md`; surface row CFG-04 (experimental). `@docsxai/viewer` exports `loadBurnTheme`, `parseThemeConfig`, `resolveBurnTheme`, `themedBurner`, `themeStyle` and the preset table.

A fourth preset, `readable`, sets `auto`, 15 px text, 10 and 14 px padding, a 0.55 `max_width_ratio` and ink on near-white at WCAG AA. Every default equals the old value, so a workspace without the keys burns the same bytes. Bad values stop the command with the key and range. Guide: `docs/burn-theming.md`.

Manifest entries that name one page id keep the first, sections whose keys collide case-insensitively and sections or titles named like the manifest page are refused before any request, and the screenshot read cap drops from 64 MiB to 21 MiB (the 20 MiB upload limit plus 1 MiB).
- **GitBook publisher: merge conflicts, caps, 429, escaping.** A merge that answered `conflicts` returned `ok: true` while the manifest in the same change request already held the new hashes, so the next push said unchanged. The push now returns `ok: false` with a masked message and resets those hashes in a second change request (`config.force` is the fallback when that fails too). Screenshots are capped at 4 MiB per page batch (the rest are captioned and named in `warnings`), page markdown at 1 MiB (refused with an error), and the screenshot read at 4 MiB instead of 64 MiB. A 429 is retried after `Retry-After` (at most 5 times, each wait at most 30 s), a change request whose id cannot be used is archived, manifest entries that share a page id and sections that collide on a slug are refused like in the Notion plugin, and text now escapes block-start characters (`#`, `-`, `+`, `=`, `1.`, `1)`) at the head of each line.
- **Confluence publisher: attachment upload.** A live run against Confluence Cloud created the page, then `POST /wiki/api/v2/pages/{id}/attachments` answered 405 METHOD_NOT_ALLOWED, because v2 only reads attachments. Uploads now go to `POST /wiki/rest/api/content/{pageId}/child/attachment` (multipart `file`, `comment`, `minorEdit`, header `X-Atlassian-Token: no-check`), a changed screenshot is posted to `.../child/attachment/{id}/data`, and the media file id comes from `extensions.fileId` in the response. Every call has a deadline that covers the response body (30 s API, 120 s upload), error bodies are masked before they are cut to 500 characters, and a failed manifest write after an earlier error logs itself and leaves the first error as the one reported. Sections that land on one path (`a b` and `a-b`, case-only differences, a flow named `index`) and different screenshots with one image name fail before any request, naming both. Code spans and fences use a backtick run longer than any inside, links are kept only for `http`, `https` and `mailto` with `(`, `)`, whitespace and brackets percent-encoded, titles, `title_prefix` and alt text lose newlines and control characters and are escaped, and heading levels are clamped to 1 to 6. `graph_base_url` is returned as the parsed origin and path, refuses a query or fragment, and accepts only `/v1.0` or `/beta`. The README no longer claims a 250 MB simple upload or parent folder creation as verified.

- **SharePoint publisher: `!` before a link.** A text node ending in `!` followed by a link-marked node rendered as `![t](url)`, which markdown viewers load as a remote image. The `!` is now escaped when a link follows it.
- **SharePoint publisher: image link and upload share one name; names checked first.** A page linked an image by `safeName(alt)` while the upload used `safeName(fileName)`, and an `alt` of `..` threw only after earlier files were written. - **SharePoint publisher: trailing dot in a name.** SharePoint strips a trailing `.`, so `a.` and `a` were one file that the collision check treated as two. `safeName` now drops trailing dots (and any dashes left behind), so both come out as `a` and are refused as a collision.
- **SharePoint publisher: names that strip to nothing, quoting in logs and errors.** `safeName` refused only all-dot names, so `.-.` or `.-.-` passed and the trailing strip left an empty string (a page `.md`, an upload path `images/`, a folder `docsxai//`); an empty result now falls back to `item` like an empty name does. The per-section log line quotes the section name with `JSON.stringify` instead of hand-written quotes, so a `"` in a name no longer breaks the quoting. - **`hide` and `show` steps.** `action: hide` sets `visibility: hidden !important` on every element its `target` matches, for the rest of the flow or until a `show` (no target lifts every `hide`; a target lifts the `hide` that used the same selector). The element keeps its box, so nothing around it reflows, and it is absent from every later screenshot, halt shots included, and hidden from the next check at once even on a page whose reduced-motion reset gives every element a tiny `transition-duration` (the rule carries `transition: none`). The driver marks the elements with a data attribute and adopts a fixed engine-owned stylesheet keyed on it, on the element's own root, so it reaches shadow trees and is not blocked by a page's CSP; the selector is only data. The driver re-marks before each screenshot, so the hiding survives navigations and re-renders. `hide` waits for a match to exist and halts if none does, unless `optional: true`. That covers the Next.js dev overlay badge (`target: nextjs-portal`); there is no general CSS-injection step and no `display: none` option (it would reflow the page). `export playwright` emits both steps.
- **Per-step `timeout_ms`.** Any step that waits on a `target` (and a `wait` step's `wait_for: { selector }`) accepts `timeout_ms`, 100 to 30000. Unset, nothing changes: the default stays Playwright's 30 s for optional and non-optional steps alike, so existing flows run as before. Set it on an optional step and a missing target is skipped in that budget instead of 30 s. Rejected on steps where it would bound nothing.
- **Lint and diagnose.** R011 (info): `optional` step with no `timeout_ms`. R012 (error): `hide` without a `target`. R013 (warning): a step targets, anchors an annotation to, or waits on an element an earlier `hide` hid. `diagnose` adds hints for a halted `hide`, for a target hidden by an earlier step, and suggests `optional` + a short `timeout_ms` on `not-found`.

- **Burned callouts on small screenshots.** On annotation records with `obstacles`, the callout is at most `min(280, 0.62 x image width)` wide, never under 168 px (242 px on a 390 px screenshot), and when that box has no clear spot the burner tries two narrower ones before settling for the least overlap. Screenshots 452 px and wider, and records without `obstacles`, keep the fixed 280 px and burn to the same bytes as before.
- **`placement` on annotations.** `docsxai/annotations@1` records and flow-file step annotations accept an optional `placement` object, still valid without it: `inside` (callout inside a target big enough to hold it, no arrow), `side` (try only that side; `arrow` stays a soft hint whose corner half is ignored), `align` (`start`, `center`, `end` along the edge), `pin_arrow` (`nudge` moves only the callout, the arrow stays on the target), `max_width` (120 to 560), and `obstacle_radius` (0 to 2000 CSS px) and `obstacle_limit` (1 to 40), which `docsxai run` uses for that annotation's obstacle scan instead of 320 px and 40 boxes. Bounded and strict like `obstacles`. The interactive viewer ignores it.
- **`docsxai-viewer burn --report <file>`.** Writes `docsxai/burn-report@1` JSON: per annotation the callout and badge boxes, the px² still covering `obstacles` and other halos, badges and callouts, the overlap as a share of the callout's area, and `unplaceable: true` when that share is above 0.1 (`--max-overlap <ratio>`). The burner still draws every annotation; the pipeline decides what to drop. `burnFlow` returns the same report, `renderBurn` returns it with the PNG.
- **`docsxai run --verify-determinism`.** `docsxai run <workspace-dir> --verify-determinism [--runs <2-5>] [--format json|md|text]` runs the selected flows 2 to 5 times (default 2), each into its own root under `<workspace>/.docsxai-verify/run-<k>/`, and byte-compares every artefact: `annotations.json`, screenshots, step markdown, locators and halt context. The report (`docsxai/verify-determinism@1`, no timestamps or paths, deterministic order) names the first differing artefact by path with a cause: the JSON key path, the changed-pixel count and bounding box of a PNG (the pixel diff `docsxai diff` uses), the first differing text line, or the sizes. Exit 0 identical, 1 differing or a flow halted, 2 bad flags (`--runs` outside 2 to 5, or any of `--pause`, `--stop-after`, `--start-from`, `--cdp`). The workspace output is written only when every run agrees (run 1's files are copied in); otherwise it is untouched. The run roots are removed at the end by their listing, with no recursive delete. Report on stdout, progress on stderr. `PlaywrightSessionOptions` gains an optional `outputRoot`, and `run`'s flow loop moves to `run-flows.ts` unchanged for a plain run. The engine exports `compareRuns`, `compareArtefactBytes` and the report formatters.
- **Nightly drift recipes.** `docs/ci-recipes.md` gains copy-paste nightly jobs for GitHub Actions (schedule and `workflow_dispatch`), GitLab CI (pipeline schedule) and Woodpecker (cron): install, `run --verify-determinism`, `diff --against <baseline> --fail-on fail`, and the markdown reports uploaded as an artifact. Runnable copies sit in `examples/ci/` (not wired into this repository's own CI), and a test checks that they parse, that every command and flag they use appears in `docsxai --help`, and that the copies in the guide match the files. The page says browser capture must not run in per-PR pipelines on shared runners. A new guide, Determinism and drift, covers reading the report and fixing what varies.
- **Deprecation helper.** `deprecation.ts` prints `docsxai: <item> is deprecated since <version>, use <replacement>` once per invocation and looks names up in a retired registry (`warnDeprecated`, `findRetired`). Its first use is the retired `drift` command.
- **`login --oauth` and `inspect --ignore-https-errors` in `--help`.** Both already worked; the usage text, the CLI reference and the contract snapshot now carry them.
- **Project `app_url`.** The backend `Project` resource gains an optional `app_url`: the base URL of the running app the project documents, an absolute `http:` or `https:` URL of at most 2048 characters with no embedded credentials. `POST /v1/workspaces/:ws/projects` takes `{ name, app_url? }`, the new `PUT /v1/workspaces/:ws/projects/:project` takes `{ app_url: string | null }` (null clears it), and an invalid value gets `400 bad_request` naming `app_url`. `BackendStore` gains `setProjectAppUrl` and `createProject` an optional third argument; `MemoryStore` and `FsStore` implement both, and existing `meta.json` files read as before. A webhook run writes it into the materialised `.docsxai.json` as `app_url`, which is what `docsxai run` uses as the base URL for relative `navigate` values. This extends the frozen backend core additively: the `backend-api` contract snapshot gains the route and the optional member, no existing field or route changes.

### Changed

### Security

- **Flow names are path-safe.** `name` (and `extends`) in a flow-file must start with a letter or digit, use only letters, digits, `.`, `_` and `-`, contain no `..` and be at most 64 characters, and `calibrate --name` follows the same rule. Before, `../.docsxai.json` passed the schema, and `run` or `run --verify-determinism` would then write under that path. A flow-file with a name outside the rule now fails to parse; uppercase letters, underscores and dots are still fine.
- **`run --verify-determinism` refuses symlinks.** A symlink in a run root stops the verification before anything is copied into the workspace, with the entry named.
- **Verify reports carry no absolute paths.** Halt messages in the report are cut to their first line and every absolute path (POSIX, Windows, UNC, `file://`) becomes `<path>`, as the report header always claimed.
- **Verify comparison is bounded.** Artefacts above 64 MiB are compared by size and then byte by byte in 1 MiB chunks, and reported as a `bytes` difference, instead of being read into memory twice.
- **`docsxai pack` checks the optimiser.** The output of `oxipng` (or whatever `DOCSX_OXIPNG_BIN` names) has to be a complete PNG with the same pixels as its input. A binary that exits non-zero, writes garbage or is lossy stops the build and is never hashed.
- **More pack guards.** Titles, captions, alt text and callouts that hold a private-network address (10/8, 172.16/12, 192.168/16, 169.254/16), an email address outside the reserved example domains, an `Authorization:` header that is not `Bearer`, or a token in a URL query (`?token=`, `key=`, `sig=`, `signature=`, `access_token=`, `api_key=`) stop the build.

- **Backend webhook runner writes a workspace the engine can run.** `SpawnRunner.materializeWorkspace` wrote each artifact slot as `<slot>.json` (`flows.json`, `annotations.json`, ...) in the temp dir, a layout `docsxai run` cannot read: it lists `flows/*.flow.yaml` and exits with `has no flows/ directory`. It now writes `flows/<name>.flow.yaml`, `docs/<flow>[/<variant>]/annotations.json`, the screenshot bytes from the blob store under `docs/<flow>[/<variant>]/screenshots/`, `docs/style.yaml`, `docs/style.json`, `docs/locators.yaml` and `.docsxai.json` (`app_url` comes from the project's `app_url`, below), the same layout `pull` produces. ## [0.2.0] - 2026-06-26

The MVP: an LLM-agnostic engine + Claude Code plugin that walks a web app, follows written flows, and emits screenshot-rich docs. Calibration is AI-assisted and rare; execution is deterministic, agent-free, and CI-friendly.

### Added

#### Bare `docsxai` meta-package

- **`docsxai` on npm is the batteries-included CLI package.** `packages/docsxai/` carries a `bin.mjs` that resolves `@docsxai/engine`'s CLI entry (new `@docsxai/engine/cli` export) and runs it **in-process** (no spawn), plus `index.mjs`/`index.d.mts` re-exporting the engine's library surface. Dependencies are exactly `@docsxai/engine` + `@docsxai/viewer` — the viewer dep is deliberate, so one `pnpm add -g docsxai` puts `docsxai-viewer` on the path and `docsxai render` works out of the box through the engine's layered viewer resolution. Gated by a real subprocess test (`init` + `lint` against a fixture workspace through the wrapper bin).

#### Engine — `docsxai doctor`

- **`docsxai doctor [<workspace-dir>]`** — environment + workspace health-check: ✓/✗ checklist with a one-line fix per failing row (− rows are informational; exit 1 on any ✗). Checks: Node >= 20; Chromium presence for playwright-core (the documented one-shot install as the fix); `.docsxai.json` found + parseable (cwd or the arg; informational when absent); every flow-file parses (count; first error fails); auth descriptor parse + cached-session freshness (expired → `capture-auth` fix hint); backend reachability via `GET /v1/health` when `backend_url` is configured (with a token-presence note); the plugin declarations through the same stage-1 inspection `plugins list` runs — declared/installed/lock/capabilities, **no plugin code executed**; viewer-bin resolution naming which of the three layers hit; and `DOCSX_*` env sanity (`DOCSX_CACHE_KEY` well-formed when set; unknown `DOCSX_*` names flagged as likely typos).

- **Workspace plugin runtime v1** — four extension points (publishers, renderers, lint-rules, auth-strategies) via a `docsxai` manifest on a plugin package's `package.json` plus a `register(api)` module. - **`docsxai export adf` + `projectDocPackToAdf`** — pure, deterministic Confluence ADF projection of the doc pack (zero HTTP): one consolidated document with anchored H2 flow sections (default `single` mode) or a parent overview + one document per flow (`page-tree`); markdown-subset → ADF converter (paragraphs, bold/em/code, links, lists, fenced code; raw HTML stays literal text); per-step `mediaSingle` nodes referencing burned PNGs (clean-screenshot fallback with a warning) plus an attachments manifest with sha256s. Writes `<workspace>/.export/adf/{projection,attachments}.json` — the artifact a host agent hands to the Atlassian MCP.
- **`@docsxai/plugin-confluence`** — first publisher plugin (`confluence:push`): Confluence Cloud REST v2 via built-in `fetch`, capability-declared `egress:*.atlassian.net` (the only Confluence egress path — the engine emits projections only). Page identity is the `{ section → pageId }` `config.page_map` (each result page echoes its `section`); idempotent via a `docsxai-content-sha` content-property — re-publishing an unchanged projection performs zero mutations, and attachment uploads are skipped when the same-name attachment carries a matching `docsxai-sha256:<hex>` comment; the API token is masked as `<CONFLUENCE_TOKEN>` in every error/log line. Verified against an in-process fake v2 server that counts mutations, loaded through the real `resolvePlugins` path.

#### Engine — execution determinism + redaction

- **`environment` block** in the flow-file (`clock` freeze, `locale`, `timezone`, `viewport` incl. `desktop`/`tablet`/`mobile` presets, `color_scheme`, `reduced_motion`) applied at session creation; per-key child-wins `extends` merge; CDP-attached sessions apply what page-level APIs allow and warn once on the rest.
- **Deterministic `redactions`** — flow-level + per-step, selector- or region-based, `box` (solid fill) or `pixelate` (16px mosaic); applied in-memory before any screenshot byte hits disk, halt screenshots included; annotation-on-redacted-target lint guard.
- **Real `element_stable`** — best-effort bounding-box stability poll (two consecutive identical reads, 10 s budget).
- **Lint R005–R010** (missing `extends` target, unused locator, terminal step without `success`, un-guarded `optional`, selector-less `element_stable`, annotation anchored to a redacted element) + injectable `extraRules` for lint-rule plugins.
- **Byte-identical determinism keystone** — frozen-clock + redacted flow re-run twice asserts identical screenshot bytes against real Chromium.
- `BrowserDriver.screenshot` gained an optional `redactions` parameter (external driver implementers take note).

#### Engine — workspace + CLI hygiene

- **`resolveWorkspacePath` / `resolveWorkspacePathReal`** — the filesystem chokepoint: every workspace artifact read/write routes through containment checks (separator-boundary prefix + realpath symlink-escape defense); typed `WorkspacePathEscapeError`.
- **In-process deterministic `docsxai zip`** (fflate) — no system `zip` binary; sorted entries, zip-epoch mtimes, fixed compression: same doc pack → byte-identical archive; workspace-escaping symlinks never archived.
- **Layered viewer-bin resolution for `render`** — `DOCSX_VIEWER_BIN` → installed `@docsxai/viewer` bin (run with current Node) → PATH, all three attempts reported on failure.
- Full library surface exported from the package root (lint / flow-tree / diagnose / style / backend-client / doc-pack-io / zip were previously CLI-only); dead in-engine pipeline Stage contract removed (the dropped calibration-stage shape — agent orchestration lives at the harness/MCP layer).

#### Engine (`@docsxai/engine`)

- **Flow-file format** — declarative YAML (`prerequisites` / `locators` / `steps[]`), `extends:` composition, schema-validated, hand-editable. Actions: `navigate` / `click` / `fill` / `upload` (file-input via Playwright `setInputFiles`) / `press` / `hover` / `select` / `check` / `uncheck` / `wait`.
- **Deterministic runtime** — `docsxai run` replays a doc pack headless with zero agent/LLM involvement; byte-identical re-runs (keystone test).
- **`optional: true` steps** — best-effort steps for conditionally-present UI (confirmation modals, first-run tooltips, cookie banners); skipped (logged, no screenshot/annotation) instead of halting.
- **Calibration aids** — `docsxai lint` (static flow-file checks), `flow-tree` (extends-graph + collision check), `diagnose` (halt context + typed recommendations), `inspect` (live-page locator discovery).
- **Fast iteration** — `run --start-from <step> --cdp <endpoint>` skips to a tail step against an already-warm Chrome; sub-3-sec inner loop on long-async flows.
- **`actionable()` predicate** — portable element-state probe (`actionable`/`disabled`/`off-screen`/`covered`/…) for browser-bridge consumers; contract in `docs/actionability-contract.md`.
- **Halt-cause prefix** — flow-execution errors lead with an inferred 1-line cause parsed from the Playwright actionability log.
- **Target-site auth** — `auth/strategy.yaml` descriptor + `manual-capture` strategy (security-lowered instrumented Chrome, local `storageState` cache, real-cookie-expiry tracking, persistent profile, `--cdp` attach).
- **Scripted auth catalogue** — unattended re-auth strategies, one module per scheme under `src/auth/`: `api-login` (redirect-chain cookie collection via an own RFC-6265 jar), `ui-form` (drive the app's login form; `pre_steps` for pre-login chrome; `options.totp` RFC-6238 hop with dep-free `generateTotp`/`verifyTotp`), `email-otp` (pluggable `InboxProvider` polling — `http-json` built-in, `code_pattern` extraction, `registerInboxProvider` hook), `webauthn` (CDP virtual authenticator attached before navigation), `jwt-injection` (static token or OAuth2 client-credentials mint; localStorage/cookie injection), `http-basic` / `pat-header` / `mtls` (connection-level context options), `test-backdoor`. Credential **user pools** (comma-separated env values; per-worker consistent pick via `resolveCreds`), `registerAuthStrategy` plugin hook consulted before the built-ins, `expiresAt` derived whenever credible (cookie expiry / JWT `exp` / `expires_in`), secret values never echoed.
- **Style artifact** — `docsxai style` init/validate + derived JSON + jargon-leak scanner (semantic-reshape enforcement).
- **Hand-off** — `docsxai zip` packages a reviewer-ready archive (excludes operator-local `.auth/`, halts, `.viewer/`).
- **Backend client** — `docsxai login` / `push` / `pull` against the stub backend (linear immutable revisions).

#### Viewer — Starlight docs site (`@docsxai/viewer`)

The single-file interactive viewer remains the zero-dependency default/embed renderer.
- **`@docsxai/plugin-starlight`** — first renderer plugin (`starlight:site`): thin adapter over the emitter/builder, zero capabilities, loaded through the real `resolvePlugins` path in tests.

#### Engine — drift detection + test export

- **`docsxai baseline` + `docsxai diff`** — deterministic drift reports (`docsxai/drift@1`): id-keyed step deltas, annotation moves beyond a px tolerance, exact RGBA screenshot pixel diffs (with `ignore_regions`), prose line-change counts, locator changes; `--format json|md|text` (the markdown form is PR-comment-ready) and a `--fail-on warn|fail` CI gate. Drift detection is engine-deterministic; the patch proposal stays an explicit agent step (`diagnose`) — never ambient.
- **`docsxai export playwright`** — one self-contained Playwright `.spec.ts` per flow (extends resolved, `environment` as `test.use()` + fixed clock, optional steps try/catch-wrapped, regenerate-don't-hand-edit header): the doc pack doubles as a regression suite.

#### Backend — GitHub App webhook surface (`@docsxai/backend`)

- **`POST /v1/github/webhook`** — HMAC-SHA-256-signature-verified (timing-safe; GitHub's documented test vector pinned), event-filtered, replay-guarded (last 100 delivery ids) webhook endpoint; per-project `webhook-config` CRUD (repo mapping, events, output strategy, revision pin). Zero YAML in user repos — config lives in the backend.
- **Run dispatch** — per-project serial `QueuedDispatcher` → `SpawnRunner`: materializes the configured revision into a temp workspace, runs the engine CLI, appends run history.

App registration, webhook URL/secret, and installation tokens are owner-gated (checklist in the backend README).

#### Backend — persistence, blobs, OAuth, encrypted cache (`@docsxai/backend`)

- **Filesystem persistence** — `FsStore` behind the new `BackendStore` interface (atomic tmp+rename writes, traversal-guarded paths), selected via `--data-dir` / `DOCSX_DATA_DIR`; the in-memory store remains the default for tests.
- **Content-addressed blobs** — `POST/GET/HEAD /v1/blobs` (sha256-addressed, deduplicated) with 10 MB JSON / 25 MB blob body limits (413). Screenshots travel as `docsxai/screenshots@2` sha256 manifests; the engine HEAD-probes, uploads, and integrity-verifies on pull (base64 payloads are gone).
- **Revision finalisation** — `POST …/revisions/:rev/finalize`; artifact PUTs afterwards are rejected 409 (`revision-finalized`); `docsxai push` finalizes — linear-immutable is now enforced, not aspirational.
- **OAuth 2.1 + PKCE** — S256-only authorization-code flow with single-use 5-minute codes, refresh-token rotation, sha256-hashed token storage; CI keeps the `DOCSX_TOKEN` bearer path. `docsxai login --oauth` runs the loopback handshake and stores tokens at `.auth/backend-token.json` (0600) with auto-refresh.
- **Encrypted storage-state relay** — `PUT/GET/DELETE /v1/workspaces/:ws/auth-cache/:role` stores client-side AES-256-GCM envelopes (`BackendStateCache`, key from `DOCSX_CACHE_KEY`); the backend never sees plaintext session state.
- **Run history wired** — `docsxai run` appends execution records to backend-bound workspaces (offline-tolerant).

#### Viewer — burn renderer + hardening (`@docsxai/viewer`)
