# Plugin and skill read-through

Read-through of `packages/plugin` (the eight commands, the `calibrate` and `diagnose` skills, `README.md`, `.claude-plugin/plugin.json`, `package.json`) and `packages/skill` (the vendorable bundle) after the `0.3.0-rc.2` CLI changes (`pack`, matrix variants, `run --verify-determinism`, `burn`, quoted `next:` hints, closing lines). The reference for "real" is `packages/engine/src/cli-usage.ts` and `docs/public-surface.md`. Read as an agent that gets the file as a prompt, and as a person who reads the README and `/help`.

No file in either package is in Spanish, so there was nothing to reconcile between languages. Names stay as the surface pins them (CC-01, CC-02): eight command names, skills `calibrate` and `diagnose`.

Tarball evidence: the published `@docsxai/plugin@0.3.0-rc.2` holds `LICENSE`, `README.md`, `package.json` and `dist/`, nothing else. It has no `commands/` (8 files), no `skills/` (2 files) and no `.claude-plugin/`. The published `@docsxai/skill@0.3.0-rc.2` has no `skill/` directory, so `vendorSkill()` has nothing to copy. Both ship with `files: ["dist"]`, so `0.3.0-rc.1` and `0.3.0-rc.2` of both packages were published without these files. With the fix, `npm pack --dry-run` of the plugin lists those 11 files (`.claude-plugin/plugin.json`, 8 commands, 2 skills) next to `LICENSE`, `README.md`, `package.json` and `dist/`.

Regression guard: `scripts/audit-package-contents.mjs` now also fails when a packed tarball lacks a required path, naming it. The rules live in `scripts/package-audit-rules.mjs`: every package must contain its `main` and each `bin` target; `@docsxai/plugin` must contain `.claude-plugin/plugin.json` and every `commands/*.md` and `skills/*/SKILL.md` in the source tree; `@docsxai/skill` must contain `skill/docsxai/SKILL.md`. The forbidden pattern for `.claude` is `/(^|\/)\.claude(\/|$)/`, which needs a `/` or the end of the path after `.claude`, so `.claude-plugin/` passes; `packages/plugin/test/package-audit-rules.test.ts` pins that, and pins the required list against the source tree.

New guard: `packages/plugin/test/cli-usage.test.ts` reads the `Usage:` block of `docsxai --help` from `cli-usage.ts`. It checks that each command wraps a real subcommand, that each `argument-hint` (leading words, flags and flag values) is a subset of that subcommand's usage lines, that every `docsxai ...` code span in a command, skill, the vendored skill and the README names a real subcommand and real flags, that `$ARGUMENTS` is quoted, that skill names match their directory, that the prose says workspace, and that no repo-only package is advertised as installable (the four wiki publishers are not named at all; `@docsxai/mcp` and `confluence:push` must sit in a paragraph that says repo-only).
