# MCP server audit: what an agent reads

Scope: `packages/mcp` (private, experimental). The audit reads the 14 tool definitions, their input schemas and their error paths the way a host agent does: from the tool list, from the result JSON, and from nothing else. It was done by reading the source. No tool was run, and no test was run locally; the new tests run in CI.

The questions asked of every tool: does the description say what it does, when to use it, what it returns and what to do on failure; do argument names agree with the CLI flags and with each other; does each argument have a description, and an enum or bound where one applies; does an error name the failed thing and a next step; can an HTTP caller learn anything about auth or about paths outside the workspace root.

Tool names and argument names are the pinned surface (`docs/public-surface.md`, MCP-01 and MCP-02) and did not change. Every change is a description, an added bound, an added result field, a message, or a refusal of input that never ran correctly (a matrix flow).

## Checked, no change needed

| Area                      | Result                                                                                                                                                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP refusals             | 400, 401, 403, 404, 405, 413, 429 and 500 are `{ "error": "<code>" }` with a fixed code. A wrong token, a missing token and a malformed header give the same 401. A bad Host or Origin gives 403 before the token is looked at. The token never appears in a message, a log line or a response.      |
| Workspace-root errors     | `the path is outside the server's workspace root` and `the path cannot be resolved inside the workspace root` do not echo the path, and an existing and a missing path outside the root give the same message.                                                                                       |
| Parameter names           | `flow`, `out`, `rev`, `kind`, `author`, `cdp` and `step` match the CLI flags. `startFrom`, `stopAfter`, `baseUrl`, `appUrl`, `includeViewer` and `ignoreHttpsErrors` are the camelCase of `--start-from`, `--stop-after`, `--base-url`, `--app-url`, `--include-viewer` and `--ignore-https-errors`. |
| Enums and bounds          | `auth`, `captureTrigger` and `kind` are enums, `concurrency` is an integer from 1 to 16.                                                                                                                                                                                                             |
| README and website tables | Both list the 14 registered tools with the right kind. The registry test pins the names; the rows are prose and were checked by reading.                                                                                                                                                             |

## Left, with the reason

| Tool                         | Finding                                                                                                                                                                | Why it stays                                                                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `run_flows`, `diagnose_halt` | No `variant` argument, so a matrix flow cannot be run or diagnosed through MCP, and `get_annotations` and `get_run_artifacts` do not look in `docs/<flow>/<variant>/`. | A new optional argument is additive but needs a browser run to test. The CLI covers it; the tools now say so. Follow-up.                     |
| `style_check`                | `check` defaults to true, where `docsxai style` scans only with `--check`. The tool also creates `docs/style.yaml` when it is absent.                                  | Changing a default changes behaviour for existing hosts. The argument description and the README say it.                                     |
| `run_flows`                  | No equivalent of `--pause` or `--verify-determinism`.                                                                                                                  | Both need a person at a terminal or a long multi-run report; out of the boundary for a tool call.                                            |
| all (HTTP)                   | Successful results carry absolute paths that include the root's own path (`workspace`, artifact paths).                                                                | They are inside the root and an HTTP client cannot open them. Returning root-relative paths would change every result shape; owner decision. |
| HTTP 401                     | The response carries `WWW-Authenticate: Bearer`, which tells a client the scheme.                                                                                      | RFC 6750 clients expect it, and the scheme is in the README. No token detail is in it.                                                       |
| `push_pack`, `pull_pack`     | The hint names `DOCSX_TOKEN` and `docsxai login`.                                                                                                                      | These are the backend credentials, not the MCP bearer token. The names are what the person on the server's machine needs.                    |
| `list_flows`                 | An empty `flows` array has no `hint`.                                                                                                                                  | The description says it is empty when no flow exists. Same pattern as `get_run_artifacts` if wanted.                                         |
