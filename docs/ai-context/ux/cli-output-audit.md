# CLI output and error audit

Read-through of `packages/engine/src/cli*.ts`, `cli-commands-*.ts`, `cli-usage.ts`, `run-flows.ts`, `verify-*.ts`, `doctor*.ts` and the viewer bin (`packages/viewer/src/index.ts`, `pack-cli.ts`). Every row is a message as it was, what was wrong with it, and what changed. "Left" rows are findings that were not changed, with the reason.

## Conventions the fixes follow

- An error says what failed, why, and the command to run next: `<command>: <what failed>` then an indented `  next: <command>`. Shared wording lives in `cli-messages.ts` (`withNext`, `usageError`, `redactUrl`), `cli-backend-errors.ts` and `cli-run-summary.ts`.
- A usage error prints the failing command's own `Usage:` lines (read from the help text, so they cannot drift) and a pointer to `--help`, not the whole help.
- The last stdout line of `run`, `calibrate`, `burn`, `pack`, `zip`, `baseline`, `push`, `pull` and `doctor` starts with the command name and gives counts and where output went.
- Exit codes, `--format json` outputs, the `Usage:` block of `--help` (CLI-02, snapshot) and every contract snapshot are untouched. No snapshot changed.
